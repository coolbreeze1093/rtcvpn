你说的应该是 **先通过 SOCKS5 的 TCP 连接建立控制通道，然后使用 UDP 代理（UDP ASSOCIATE）**，而不是“TCP 流量转换成 UDP”。

SOCKS5 的流程是这样的：

```
Client                 SOCKS5 Proxy              Target UDP Server
  |                         |                           |
  |---- TCP connect ------->|                           |
  |                         |                           |
  |<--- SOCKS5 greeting --->|                           |
  |---- UDP ASSOCIATE ----->|                           |
  |                         |                           |
  |<--- UDP relay address --|                           |
  |                         |                           |
  |========= UDP ==========>|========= UDP ============>|
```

### 1. TCP阶段：协商 UDP Relay

客户端先建立 TCP：

```
Client -> Proxy TCP:1080
```

完成 SOCKS5 握手：

#### Greeting

客户端：

```
+----+----------+----------+
|VER | NMETHODS | METHODS  |
+----+----------+----------+
| 05 |    01    |    00    |
+----+----------+----------+
```

服务器：

```
05 00
```

表示 SOCKS5，无认证。

---

### 2. 发送 UDP ASSOCIATE 请求

客户端通过 TCP 发：

```
+----+-----+------+----------+----------+
|VER | CMD | RSV  | ATYP     | DST.ADDR | DST.PORT |
+----+-----+------+----------+----------+
```

其中：

```
VER = 0x05

CMD:
0x01 CONNECT
0x02 BIND
0x03 UDP ASSOCIATE
```

所以 UDP ASSOCIATE：

例如：

```
05 03 00 01 00 00 00 00 00 00
```

含义：

```
05       SOCKS5
03       UDP ASSOCIATE
00       保留
01       IPv4
00000000 任意地址
0000     任意端口
```

---

### 3. Proxy 返回 UDP Relay 地址

服务器返回：

例如：

```
05 00 00 01 C0 A8 01 10 27 10
```

解析：

```
05       SOCKS5
00       成功
00       RSV
01       IPv4
C0A80110 192.168.1.16
2710     UDP端口10000
```

之后客户端向：

```
192.168.1.16:10000
```

发送 UDP。

---

### 4. UDP包格式

真正发出的 UDP 数据不是裸 UDP，而是：

```
+------+-------+------+----------------+------+---------+
| RSV  | FRAG  | ATYP | DST.ADDR       | PORT | DATA    |
+------+-------+------+----------------+------+---------+
 2B      1B      1B       variable       2B    variable
```

例如：

客户端想访问：

```
1.2.3.4:53
```

UDP payload：

```
00 00        RSV
00           FRAG
01           ATYP IPv4
01 02 03 04  DST.ADDR
00 35        PORT
xxxx         DNS数据
```

代理收到后：

```
去掉 SOCKS5 UDP Header
        |
        v
发送裸UDP:
1.2.3.4:53
```

---

### 关键点

SOCKS5 **不会把已有 TCP 连接里的数据改造成 UDP**。

它是：

* TCP连接：只负责**控制协商**
* UDP连接：负责**实际数据转发**

也就是：

```
TCP:
握手
认证
申请UDP代理
获取UDP relay地址

UDP:
数据传输
```

如果你看到某个程序是：

```
TCP连接建立
↓
协商
↓
后续同一个TCP连接里传UDP数据
```

那不是标准 SOCKS5 UDP ASSOCIATE，而是某种 **TCP tunnel / UDP encapsulation 私有协议**。



对，在 SOCKS5 UDP Relay 里面，去掉 UDP Header 后剩下的全部就是原始 UDP 数据（DATA）。

结构：

SOCKS5 UDP Packet

+--------+-------+------+----------------+----------+----------+
|  RSV   | FRAG  | ATYP | DST.ADDR       | DST.PORT | DATA     |
+--------+-------+------+----------------+----------+----------+
| 2字节  | 1字节 |1字节 | 可变           |2字节     | 剩余全部 |
+--------+-------+------+----------------+----------+----------+

例如你之前的包：

00 00 00 01 ac 17 60 01 c1 13 00 4c 21 12 a4 42 ...

解析：

00 00          RSV
00             FRAG
01             ATYP IPv4

ac 17 60 01    目标IP = 172.23.96.1

c1 13          目标端口 = 49427

00 4c 21 12... DATA

所以发送给目标时：

去掉：

00 00 00 01 ac 17 60 01 c1 13

剩下：



1. IPv4 (ATYP = 0x01)

例如：

00 00 00 01 C0 A8 01 10 27 10

解析：

00 00       RSV
00          FRAG
01          ATYP IPv4

C0 A8 01 10
             192.168.1.16

27 10
             10000

地址长度固定：

4 字节 IP
2 字节端口
2. Domain (ATYP = 0x03)

格式：

00 00 00 03 LEN DOMAIN PORT

例如：

00 00 00 03 0B example.com 00 50

解析：

00 00
RSV

00
FRAG

03
ATYP DOMAIN

0B
域名长度=11

example.com
